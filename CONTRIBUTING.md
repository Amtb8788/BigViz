# Contributing to BigViz

Thanks for helping. Issues and pull requests are welcome.

## Licence hygiene (read this first)

BigViz is MIT. Everything in the repo must be original work written for BigViz.

- Do not vendor or paste third-party prompt libraries, prompt packs, skill packs or scripts,
  even "free" ones, unless their licence is MIT-compatible and you add attribution. When in
  doubt, leave it out.
- Do not copy prompts, skills or docs from commercial products or paid courses.
- Example data must be fictional: no real people, customers, project names or internal
  numbers. Use names like "Team A1" and "J. Doe".
- Never commit API keys, tokens, `.env` files or generated images that contain client data.
  CI runs gitleaks on every push.
- Images under `docs/media/` must be generated by you with BigViz or created by you.

## Repository layout

The contract is [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). If you change a command, path or
spec field, update every consumer (CLI, template, skills, docs) in the same pull request.

- `cli/`: the Python `bigviz` package and its tests
- `templates/vue3-echarts/`: the Vue 3 screen template
- `plugins/bigviz/skills/`: Agent Skills
- `plugins/bigviz/commands/`: Claude Code slash commands
- `docs/`, `examples/`

## Development

CLI:

```bash
cd cli
uv sync
uv run pytest
```

Template:

```bash
cd templates/vue3-echarts
npm ci
npm run typecheck
npm run build
```

## Skills

Each skill is a folder with a `SKILL.md`:

- Frontmatter has only `name` and `description`.
- `name` equals the folder name, kebab-case, at most 64 characters.
- `description` is at most 1024 characters, has no angle brackets, and lists trigger
  phrases in English and Chinese.
- The body is imperative, concise and under 300 lines. Details go in `references/`
  (one level deep). No README inside skill folders.
- Call the CLI as `bigviz <cmd>`; never hard-code an API key.

CI checks these rules.

## Presets

A preset is `cli/src/bigviz/presets/<name>.yaml` (format in the architecture doc). Include a
contact sheet of 2–3 renders in your pull request so reviewers can judge it.

## Pull requests

- One topic per pull request; Conventional Commits for messages (`feat(cli): …`).
- Tests for CLI changes; screenshots for template or preset changes.
- CI must be green.
